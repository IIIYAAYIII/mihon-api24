# Mihon API 24 (Android 7.0+ arm64-v8a Backport)

## 1. Project Overview & Purpose

This project is a fork of [Mihon](https://github.com/mihonapp/mihon) (the open-source manga reader for Android).

- **Objective**: Adapt and backport Mihon to install and run reliably on **Android 7.0 / 7.1 devices (API level 24 / 25)** specifically targeting the **`arm64-v8a`** CPU architecture.
- **Maintainer**: Community Contributor (Runtime Obfuscated)
- **Upstream Baseline**: Official Mihon requires Android 8.0+ (API 26+).
- **Version Identifier**: `24.0` (indicates API 24 minimum SDK target).
- **Current Status**: The generated APK installs and runs cleanly on Android 7.0+ devices.

## 2. Architecture & Compatibility Adaptations

### 2.1 SDK & Build Configuration
- **Minimum SDK**: Lowered `android-sdk-min` from `26` to `24` in `gradle/mihon.versions.toml`.
- **Target ABI Splitting**: Configured `splits.abi` in `app/build.gradle.kts` to strictly compile and generate `arm64-v8a` APKs (`isUniversalApk = false`, `include("arm64-v8a")`).
- **Legacy Native Packaging**: Enabled `packaging { jniLibs { useLegacyPackaging = true } }` in `app/build.gradle.kts` to ensure `.so` shared libraries are properly extracted into the app directory on Android 7.x systems.
- **Widget Module Removal**: The home screen widget module (`presentation-widget`) relies on Jetpack Glance (which requires API 26+). It has been excluded from `settings.gradle.kts`, `app/build.gradle.kts`, and its initialization has been stripped from `App.kt`.

### 2.2 Extension Management & Permissions
- **Keiyoushi Extension minSdkVersion Bypass**: Upstream extension repositories (e.g. Keiyoushi) build all extension APKs with `minSdkVersion = 26`. On Android 7.0 (API 24), Android's internal `PackageParser` rejects them with `INSTALL_PARSE_FAILED_OLDER_SDK`, causing `PackageManager.getPackageArchiveInfo()` to return `null` and failing verification during download and loading. `PackageParserPatcher` uses runtime reflection and `sun.misc.Unsafe` to modify `PackageParser.SDK_VERSION` to `10000`, allowing Android 7's framework parser to successfully parse extension APK manifests and signatures.
- **Runtime DEX Version Downgrade (DexPatcher)**: When extensions are compiled for `minSdkVersion >= 26`, D8 defaults to the DEX 038 bytecode header format (`dex\n038\0`). Android 7.0/7.1 (API 24/25) ART runtime strictly recognizes only DEX version `035` and `037` (`ERROR: Unsupported DEX version '038'`), failing to load classes and throwing `ClassNotFoundException: Didn't find class "keiyoushi.source.Generated" on path: DexPathList[...]`. `DexPatcher` intercepts extension loading on API < 26, verifies and downgrades DEX 038/039 headers to 035, updates Adler32 checksums and SHA-1 signatures, and caches the patched APK in `codeCacheDir/patched_exts/` for `DelegateLastClassLoaderCompat`. The original `.ext` file in `filesDir/exts/` remains pristine and unmodified to ensure cryptographic signature and certificate checks pass.
- **Extension Reflection Protection (`headers$delegate`)**: Keiyoushi generated extension classes (`keiyoushi.source.Generated`) use reflection (`HttpSource.class.getDeclaredField("headers$delegate")`) to inject dynamic HTTP headers into `HttpSource`. Because `headers$delegate` is a private synthetic field generated by Kotlin's delegated property `val headers by lazy`, traditional ProGuard rules targeting `{ public protected *; }` allowed R8 in full mode to optimize/inline this private field away, resulting in `NoSuchFieldException: No field headers$delegate in class Leu/kanade/tachiyomi/source/online/HttpSource;`. Resolved by preserving all fields and members (`{ *; }`) for `eu.kanade.tachiyomi.source.**` and `eu.kanade.tachiyomi.network.**` in both `source-api/consumer-proguard.pro` and `app/proguard-rules.pro`. Furthermore, `DexPatcher.cleanIfAppUpdated` purges cached patched APKs (`patched_exts`) and ART odex caches (`ext_opt`) whenever the host app's `versionCode` increases or `base.apk` is modified.
- **Private Extension Installer Enforcement**: In `ExtensionInstallerPreference.kt`, Android versions prior to 8.0 (`Build.VERSION.SDK_INT < Build.VERSION_CODES.O`) lock the installer option to `ExtensionInstaller.PRIVATE`. Extensions are installed internally into private storage (`filesDir/exts`) and loaded via `DelegateLastPathClassLoader` (`BaseDexClassLoader`), completely avoiding system package installer restrictions and unknown sources permissions.
- **Package Install Permissions**: In `Permissions.kt` and `PermissionStep.kt`, calls to `packageManager.canRequestPackageInstalls()` (introduced in API 26) are skipped for API < 26 to prevent runtime `NoSuchMethodError` crashes.
- **Settings Navigation Fallbacks**:
  - `ContextExtensions.kt`: When requesting unknown sources permission on API < 26, navigates to `Settings.ACTION_SECURITY_SETTINGS` instead of `Settings.ACTION_MANAGE_UNKNOWN_APP_SOURCES`.
  - `SettingsAdvancedScreen.kt`: Notification management navigation falls back to application details settings (`Settings.ACTION_APPLICATION_DETAILS_SETTINGS`) on Android < 8.0.

### 2.3 Graphics & Image Rendering Compatibility
- **Hardware Bitmaps**: In `MangaCoverDialog.kt`, bitmap copying guards against `Bitmap.Config.HARDWARE` (API 26+) by falling back to `Bitmap.Config.ARGB_8888` on Android < 8.0.
- **HDR Image Decoders**: In `ImageDecoder.kt` and `ImageUtil.kt`, `Bitmap.Config.RGBA_F16` (API 26+) is guarded and falls back to `Bitmap.Config.ARGB_8888` on API < 26.
- **Adaptive Icons & Legacy Launcher Icons**:
  - Android 8.0 introduced `<adaptive-icon>`, which fails XML inflation on Android 7.
  - Adaptive icons are preserved in `mipmap-anydpi-v26/` (`ic_launcher.xml` and `ic_launcher_round.xml`).
  - Previously, the legacy fallback simply wrapped the 108dp uncropped adaptive layers in a `layer-list`, resulting in the icon appearing roughly 50% smaller ("比原版小一圈") with white corner borders on Android 7 home screens.
  - Resolved by generating properly scaled multi-density raster icons (`ic_launcher.png` and `ic_launcher_round.png`) across `mipmap-mdpi`, `hdpi`, `xhdpi`, `xxhdpi`, and `xxxhdpi` (with exact 44dp circular safe-zone footprint and transparent edges), and updating `mipmap/ic_launcher.xml` to a properly dimensioned 48dp vector.

### 2.4 System & Network Backports
- **WebView Package Inspection**: In `WebViewUtil.kt`, `WebView.getCurrentWebViewPackage()` (API 26+) is replaced with `WebViewCompat.getCurrentWebViewPackage(context)` from `androidx.webkit`.
- **Notification Channels**: In `Notifications.kt`, `createChannels()` immediately returns on `Build.VERSION.SDK_INT < Build.VERSION_CODES.O`, avoiding unnecessary channel registration and group creation overhead.
- **Active Notifications Safety**: In `NotificationReceiver.kt`, access to `notificationManager.activeNotifications` is safely caught with `runCatching` / `try-catch` to guard against `SecurityException` on OEM-modified Android 7 ROMs.
- **Network Capabilities Enum**: In `NetworkExtensions.kt`, transport capability checks avoid accessing constants like `TRANSPORT_WIFI_AWARE` and `TRANSPORT_LOWPAN` on API levels below 26/27.
- **TLS 1.3 / Network Security**: Bundled Conscrypt is initialized on Android < 10 in `App.kt` to ensure modern TLS 1.3 and HTTPS cipher suite support.

### 2.5 APK Size & Footprint Optimization (arm64)
- **WebGPU Engine Exclusion (Option A)**: Stripped `libwebgpu_c_bundled.so` (~3.21MB compressed, 9.27MB uncompressed) via `packaging.jniLibs.excludes += listOf("**/libwebgpu_c_bundled.so")` in `app/build.gradle.kts`. WebGPU is not supported on Android 7 Vulkan/OpenGL ES environments. Bypassed `WebGpuViewer` in `ReadingMode.kt` in favor of mature native viewers (`L2RPagerViewer`, `R2LPagerViewer`, `VerticalPagerViewer`, `WebtoonViewer`), disabled `useNewRenderer` in `MangaCoverDialog.kt`, and hid the toggle in `SettingsAdvancedScreen.kt`.
- **Native Debug Symbols Stripping**: Removed `keepDebugSymbols` in `app/build.gradle.kts` so that `llvm-strip` strips DWARF symbols from native libraries (`libquickjs.so`, `libconscrypt_jni.so`, `libarchive-jni.so`, `libsqlite3x.so`), saving ~10MB.
- **Telemetry & Firebase Exclusion**: Built with `-Pinclude-telemetry=false` in CI to substitute Firebase and Google Play dependencies with `noop` stubs, eliminating ~3.5MB of unnecessary telemetry code on Android 7 devices.
- **Resource Trimming**: Configured `resourceConfigurations += listOf("en", "zh", "zh-rCN", "zh-rTW", "zh-rHK")` in `defaultConfig` to strip 80+ unused locale translations, reducing `resources.arsc` by ~1.5MB.
- **R8 Full Mode & Obfuscation**: Enabled `android.enableR8.fullMode=true` in `gradle.properties` and removed `-dontobfuscate` in `proguard-rules.pro` (while protecting extension APIs via `source-api/consumer-proguard.pro`), shrinking DEX symbol tables by ~2.5MB.
- **Metadata Exclusion**: Excluded `DebugProbesKt.bin`, `**/*.proto`, and `META-INF/*.kotlin_module` in `packaging.resources.excludes`.
- **Net Result**: APK size is reduced from ~32MB down to ~15.2MB (over 52% total reduction) with zero impact on normal reading and extension capabilities.

### 2.6 UI & About Screen Attribution
- **About Screen Credit**: Added dedicated adaptation attribution in `AboutScreen.kt` located directly beneath the app Version item.
  - **Localized Content**: Included `about_android7_backport_title` and `about_android7_backport_summary` across `base/strings.xml`, `zh-rCN/strings.xml`, and `zh-rTW/strings.xml`.
  - **Credits**: Prominently notes that the release is based on the original Mihon project, backported for Android 7.0+ (API 24, arm64) devices, and maintained as a community backport (author string decoded at runtime to protect privacy from public code crawlers).

## 3. Automated Build & Release CI Workflow

The workflow file is located at [`.github/workflows/mihon-api24.yml`](.github/workflows/mihon-api24.yml).

- **Trigger Method**: Triggered manually via `workflow_dispatch` from the GitHub Actions tab.
- **Inputs**:
  - `dist`: Distribution type (`ci` or `local`, default: `ci`).
  - `create_release`: Whether to publish to GitHub Releases (default: `true`).
  - `tag_name`: Release tag name (default: `v24.0`).
- **Pipeline Steps**:
  1. Checks out repository.
  2. Sets up JDK 21 (from `.github/.java-version`).
  3. Executes `./gradlew assembleRelease -Pdist=ci`.
  4. Generates and renames release APK to `mihon-${tag_name}-arm64-v8a.apk`.
  5. Uploads the APK to GitHub Actions Artifacts.
  6. Publishes or updates GitHub Releases with the arm64 APK asset attached.

## 4. Key Rules for Future Modifications

When adding features, upgrading libraries, or modifying code:
1. **Never use Android 8.0+ (API 26+) APIs unconditionally**. Always guard with `if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O)` and provide a functional fallback for API 24/25.
2. **Watch for XML resources**: Do not introduce `<adaptive-icon>`, `android:fontFamily` without compat namespace, or Oreo-only XML attributes into unqualified resource directories.
3. **Keep ABI restricted to `arm64-v8a`**: Do not remove ABI splits or change `useLegacyPackaging = true` unless intentionally refactoring build outputs.
4. **Preserve private extension loading**: Keep `ExtensionInstaller.PRIVATE` functional as Android 7 lacks modern package installation session APIs.
